# Specifications

Specifications record feature intent, acceptance criteria, measurements, and implementation notes.
They are not automatically descriptions of the current build.

Before using a specification as context:

1. Route through [the context index](../context-index.md).
2. Check its date and metadata.
3. Verify named symbols and acceptance tests against current code.
4. Treat “not implemented”, schema numbers, test counts, file sizes, and line references as
   point-in-time claims unless current evidence confirms them.

New or substantially revised specifications should use the metadata contract in the context index
and state their current implementation status near the top.
