# Placeholder art – the shipping list

**For the owner.** This is the list of every shipped asset that is *not the real thing yet*: a file
that is a byte copy of another rung's master, or a file that does not exist at all because the code
borrows a neighbour's. Work down the table when you make the real files – each row names exactly
what is standing in for what.

**Why it exists.** Two waves landed placeholders that were honestly reported at the time and then
findable only inside an agent's report: the W2-LADDER trophies (02.08) and act 3's four top rungs
plus the three professional sponsor rungs (04.08). Nothing in the repo would have told anyone
afterwards. `tests/art-placeholders.test.ts` now keeps this file honest in both directions, so the
list cannot rot and the next wave cannot add a stand-in silently.

**No builder invents art.** Every shipped image is the owner's (AI-generated by him, processed in
Figma – see [`public/images/README.md`](../public/images/README.md) for the provenance attestation).
Deriving, recolouring or generating a replacement is not a builder's job; flagging the gap is.

## How to clear a row

1. Drop the real master into `public/images/<set>-jpeg/` and let the build encode it (or write the
   `.webp` straight into `public/images/<set>/`).
2. Run the suite. `tests/art-placeholders.test.ts` will fail with a message naming this file and the
   row to delete – that failure is the reminder, not a problem with your art.
3. Delete the row. Green.

For an `absent` row there is one extra step, named in the row's own note: **the code branch that does
the borrowing goes too**, and it goes in the same commit as the row – remove one without the other
and the guard is red in one direction or the other. The sponsor letterheads are the worked example,
start to finish: `sponsorArtKey` redirected three rungs onto `global.webp`, three `absent` rows
registered it, and on 05.08 the marks arrived, the function was **deleted** (not left as an identity –
a redirect nobody can tell is dead is worse than the redirect) and the three rows came out together.

### What the two kinds mean

- **`byte-copy`** – the file ships and is byte-identical to `counterpart`. The guard hashes both. The
  day the real master replaces it the hashes differ, the suite fails naming this row, and the row
  comes out. Copies rather than a code alias is deliberate for the trophies: the naming scheme stays
  uniform, `tests/trophy-podium.test.ts` keeps checking both directions exactly, and shipping the
  real art replaces a file instead of deleting a code path (`src/art/trophies.ts` header).
- **`absent`** – the file does not ship at all and a code branch borrows `counterpart`. The guard
  asserts the absence. The day the file appears the suite fails naming this row.
