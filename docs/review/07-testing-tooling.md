# Testing & Tooling

## Verdict

This is one of the strongest test cultures I have reviewed on a solo project: 2054 deterministic tests, a golden-save corpus that mechanically enforces backward compatibility from v0 to v34, an RNG draw-stream fingerprint that catches a single misplaced random draw, and CI decisions argued in writing next to the code they change. The suite's blind spot is equally clear: not one Vue component is ever mounted – the entire UI layer is guarded by regex pins over source text, which is inventive but brittle (334 documented re-pins) and cannot catch a runtime error in a screen. The most urgent item is new and concrete: `npm run test:sim` exits 1 with all 60 tests passing (reproduced twice locally – vitest's birpc `onTaskUpdate` timeout), so the weekly calibration workflow will be red on green from its first scheduled run. Fix that, add a thin mounted-smoke-test layer for the 10 screens, and add coverage measurement so the suite's confidence can be quantified.

## Strengths

- **Scale and hygiene.** 88 unit files / 1994 tests plus 3 sim files / 60 tests, all green; zero `.skip`, `.todo` or `.only` anywhere in tests/ (verified by grep). Unit project: 23s wall locally. `vue-tsc -b --force`: 4s.
- **Determinism as a discipline, not a slogan.** A frozen main-stream capture (41550 draws, FNV hash e6b0c709, seed `bench-working-0`, 52 ticks) is re-derived independently in five suites (tests/knock.test.ts:126, tests/injuries.test.ts:55, tests/condition.test.ts, tests/travel-home.test.ts:396, tests/trophy-podium.test.ts). Any feature that adds or reorders a draw on the main RNG stream fails loudly. The sub-stream convention (`seed:knock:<week>`, `seed:injury:<week>`) is what made the pin stable, and the tests prove each new feature honors it. `Math.random` survives only in UI cosmetics (confetti, name picker) – verified by grep.
- **Golden saves corpus.** tests/fixtures/saves holds one fixture per schema version v0–v34; goldenSaves.test.ts fails the moment `SAVE_SCHEMA_VERSION` is bumped without a new fixture, and each modern fixture is the real migration's own output on the previous one. The fixtures README documents every hop's backfill decision. This locks the project's hardest product guarantee.
- **Statistically sound calibration.** tests/match/calibration.test.ts uses fixed string seeds (zero flake by construction) and sane bands: equal players in [0.48, 0.52] at n=20k (SE about 0.0035, so the band is 5+ sigma), MC within 0.015 of the closed form at n=50k, hold-rate bands per tour/surface at n=10k. These detect a changed model, never a bad roll. Engine math is triangulated: closed-form vs reference curves vs Monte-Carlo (tests/match/closedForm.test.ts).
- **Benches are dashboards, but their harnesses are pinned.** econ-bench.test.ts and fatigue-bench.test.ts assert byte-identical reruns, accounting identities (net == income − expense == sum of per-season folds) and an independent re-derivation of the condition formula from the ECONOMY knobs. Tools and tests are typechecked under strict TS (tsconfig.app.json includes both).
- **A DOM-free UI gate that actually works.** tests/design-tokens.test.ts statically proves every `var(--x)` in src/ resolves and that design-system tokens are declared exactly once – closing the silent CSS custom-property fallback bug that had shipped twice before.
- **Save layer under fake-indexeddb** including raw-DB tampering, corruption rejection and future-schema rejection (tests/saves.test.ts, tests/migrations.test.ts:455).
- **CI honesty.** Forced typecheck in all three pipelines with the cached-TS2300 incident documented beside it (ci.yml:16, .gitlab-ci.yml:9); deploy split into build/deploy with the artifact-poisoning post-mortem in the file; the Monte-Carlo eviction from the PR gate argued in a 40-line header rather than smuggled in.

## Findings

**[HIGH] `npm run test:sim` exits 1 with every test passing** – .github/workflows/simulation.yml:38, vite.config.ts (sim project). Reproduced twice out of two runs on an idle 10-core Mac (vitest 3.2.7): summary reads `Test Files 3 passed, Tests 60 passed, Errors 1 error`, exit code 1, with `Error: [vitest-worker]: Timeout calling \"onTaskUpdate\"` fired during econ-bench.test.ts (64s in one file). The weekly workflow (added 30.07; first scheduled run is Monday 03.08) runs exactly this command on a 2-core runner. The team's own analysis says a gate that fails for non-code reasons teaches people to ignore it – that gate is about to start crying wolf weekly. Fix direction: split econ-bench.test.ts so no single file runs 60+ seconds (the reach-tracker describe alone is ~40s), or set `fileParallelism: false` for the sim project, or upgrade/patch vitest where the birpc timeout became configurable; then verify via `workflow_dispatch` before Monday.

**[HIGH] No runtime component layer – no Vue component is ever mounted** – package.json devDeps have no @vue/test-utils, testing-library, jsdom or happy-dom; the vitest environment is `node`. MatchViewer.vue (2235 lines), TournamentFlow, OnboardingWizard and all 10 screens are guarded exclusively by regex pins over SFC source text (45 of 73 root test files call `readFileSync` on source). No test executes a click handler, watcher or the worker round-trip; a thrown error in a screen's `setup()` passes the entire suite and both CI gates (vue-tsc and `vite build` catch template/type errors, not runtime logic). Fix direction: add happy-dom + @vue/test-utils and one smoke test per screen (mount with a fixture snapshot, assert it renders and the primary action emits) – roughly a day of work for a class of failures nothing currently sees.

**[MEDIUM] Source-pin brittleness and maintenance tax** – tests/screen-i-live-match.test.ts:53 pins the comment phrase `REPLACES the point log` (prose, not behavior); line 64 matches exact attribute order (`v-if=\"...\" class=\"mv-live\"`), so a harmless attribute reorder breaks it. 334 `RE-AIMED`/`RE-PINNED` annotations across tests/ record pins re-targeted after behavior-preserving refactors, and the `templateOf` slicing helper already misfired once (documented at the top of the same file). The style is a conscious choice and the annotations are exemplary – but each pin is a tax on every refactor, and a green pin says little about the running app. Fix direction: as the mounted-smoke layer lands, retire pins that assert comments or attribute order; keep the ones pinning genuine decisions (gating conditions, data sources).

**[MEDIUM] No linter or formatter** – no eslint/prettier/biome config or dependency anywhere; the only static gate is strict vue-tsc (which is well configured: noUnusedLocals, noUnusedParameters, noFallthroughCasesInSwitch). Nothing catches Vue-specific pitfalls, floating promises or style drift across 90+ source files and 20 tools. Fix direction: eslint flat config with vue + typescript-eslint recommended rules, wired into `npm run check` and both CI test jobs; expect a one-time cleanup PR.

**[MEDIUM] No coverage measurement** – no @vitest/coverage-v8, no coverage script, nothing in CI. With world.ts at 5293 lines and diary.ts at 2814, which branches the 2054 tests actually reach has never been measured. Fix direction: add `vitest run --project unit --coverage` locally (not as a gate), read the report once – engine files at high coverage will confirm the suite's strength, and the gaps will name the next tests to write.

**[MEDIUM] Pre-merge calibration is convention-only, and GitLab never runs it** – simulation.yml:17 states the working rule: touch the match model, run `test:sim` yourself, paste the numbers in the PR. That is discipline, not a gate; .gitlab-ci.yml runs the unit project only, so the second remote never executes calibration at all. Combined with the exit-1 finding, calibration currently has no reliable automated execution anywhere. Fix direction: fix the exit code first; then consider a lightweight path filter (PRs touching src/engine/match/** trigger the sim job) so the convention has a net under it.

**[MEDIUM] The unit gate is drifting back toward the contention cliff** – tests/radar.test.ts measured 22.5s locally, i.e. slower than match/calibration.test.ts was (21.8s per vite.config.ts's own note) when it earned eviction to the sim project. The unit run is 169s CPU in 23s wall on 10 cores; the config documents 231s CPU in 90s wall on the 2-core CI runner and a testTimeout already raised to 20s purely as a contention budget (radar's 6s tests × 2.5 oversubscription ≈ 15s – close). Nothing forces a new heavy file into HEAVY_SIM_FILES. Fix direction: move radar.test.ts's live-career sweeps to the sim project (keep its contract tests in unit), and add a trivial meta-test that fails when any unit file exceeds a wall-time budget, so classification stops being manual vigilance.

**[LOW] Migration hop tests are uneven v13–v32** – migrations.test.ts asserts hop semantics for v0–v12 and v33→v34; dedicated hop tests for later versions exist only in coachTiers, knock, offers and trophy-cabinet test files. The remaining hops ride on goldenSaves structural invariants, which check shape and ranges but not the backfill values the fixtures README describes so carefully. Fix direction: when a hop's backfill is subtle (v25 groundstrokes share-of-headroom, v28 seasonRecord reconstruction), one semantic assertion in the owning feature file is enough – audit against the README table once.

**[LOW] Review-round file naming hides coverage** – round9 through round13-nav, wave-b-points, redesign-home, redesign-onboarding: 13 files keyed to the review that spawned them. Coverage for one screen is split across up to four files. Fix direction: opportunistic renames/merges when files are next touched; no big-bang reshuffle needed.

**[LOW] Small-sample bench numbers quoted without noise bounds** – tools/knock-rate.ts:8 quotes design-driving figures (push doubles injury rate: 0.63 vs 0.33/season) from 24 career-seasons with no dispersion. Directionally fine, but digits from n=24 should not be copied into specs as facts. Fix direction: either bump SEASONS/careers (it is a hand-run tool, it can afford 5 minutes) or print a min–max alongside the mean.

## Recommendations

1. **Before Monday:** fix the sim project's exit code (split econ-bench.test.ts or disable file parallelism for the sim project; verify with `workflow_dispatch`). A weekly job that is red on green will be ignored within a month, and it guards the match model – a pillar.
2. **This wave:** add happy-dom + @vue/test-utils and a mounted smoke test per screen; start with MatchViewer and TournamentFlow, the two biggest untested runtime surfaces.
3. **This wave:** move radar.test.ts's sweeps to the sim project and add a wall-time budget check, so the unit gate stops re-accumulating Monte-Carlo weight.
4. **Next wave:** add eslint (flat config, vue + ts recommended) to `npm run check` and both CI pipelines; run coverage once locally and file the gaps it names.
5. **Ongoing:** when touching a source-pin test, ask whether a mounted test would pin the same decision more durably; retire pins that assert comments or attribute order.
