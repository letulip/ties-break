# Дизайн-система: Tennis Parent (мобильная игра)

Это папка дизайн-хендоффа. Если задача касается UI игры — читай её **до** написания кода.

## Порядок чтения
1. `README.md` — принципы, все 8 экранов покомпонентно с точными значениями, взаимодействия,
   игровой стейт, список компонентов на вынос, список арт-слотов.
2. `tokens.css` (или `tokens.json`) — единственный источник цветов, шрифтов, радиусов, теней, отступов.
3. `screenshots/*.png` — сверка композиции и пропорций.
4. `design/Home Screen.dc.html` — исходный HTML-прототип всех 20 экранов (референс, не продакшн-код).

## Правила
- **Не копируй разметку из `design/`.** Это прототип с inline-стилями. Воссоздавай экраны
  в существующем стеке проекта, его компонентами и паттернами.
- **Не подбирай цвета и размеры на глаз и не пипеткой из PNG.** Только значения из `tokens.css`
  и спецификаций в `README.md`. Fidelity — high, значения финальные.
- **Не вводи новые цвета.** Акцент один: `--accent-lime` (#cfe152). Если нужен оттенок —
  бери из уже объявленных токенов.
- `design/support.js` и `design/image-slot.js` — рантайм прототипа, в продакшн не переносить.
- Все изображения в прототипе — пустые слоты. Реальные арты и их размеры — таблица в разделе
  Assets в `README.md`.
- Базовый логический размер экрана 390×844 pt; gutter контента 14px (онбординг N–S — 22px);
  шаг сетки календаря 68px = 2 часа.
- Персонаж-дочь в A–M зовётся Bianca Tran, в N–T — Naomi Steiner. Это одна роль; имя приходит
  из онбординга. Не «исправлять» одно под другое.

## Что реализовывать первым
Компоненты 1–7 из раздела «Переиспользуемые компоненты» в `README.md`
(ScreenShell, TabBar, Card, Eyebrow, PaperNote, Polaroid, ProgressRing) — на них держатся все экраны.
