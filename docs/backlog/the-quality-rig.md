| 31 | ⚠ **`git diff -- <path>` TAKES AN UNCOMMITTED FIX INTO THE MUTATION PATCH, AND `git apply -R` THEN REVERTS BOTH** – hit independently by two builders on 26.09, in the same wave, in different files. The house method for a mutation arm is «edit `src/`, run, revert with `git apply -R`» precisely because `git checkout -- <file>` is forbidden in a shared checkout. It is silent when the fix under test is still uncommitted in the same file: the captured patch contains fix + mutation, the reverse-apply removes the fix as well, and the next run measures a tree nobody intended. Nothing was lost either time because both noticed, which is the whole problem – it is a hazard that hides in a green. ⚠ **The order that makes it safe is COMMIT THE FIX, THEN MUTATE, THEN REVERT**, and it belongs beside the existing `git checkout -- src` note, which warns about the index and not about this.
